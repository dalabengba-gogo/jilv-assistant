【这是什么】
MuMu 模拟器《大话西游》手游自动化框架：
截图识别 → 点击 → 再识别 的可编辑脚本循环。
支持：登录闭环 / 日常全家桶(组队一条·地煞星·师门·五环·域外·领奖)
     / OCR 定位 / 多开并行(最多5账号) / 定时任务 / 模板采集 GUI。

【目录结构】
  启动助手.bat        双击启动 GUI(无黑窗)
  启动助手(调试).bat  启动失败时用这个看报错
  验证完整性.bat      校验这个包有没有被人改过/下载坏了(见下节)
  清理残留进程.bat    ★ 删不掉本文件夹时双击它(见【退出与残留进程】)
  使用说明.txt        本文件
  runtime\            自带 Python 3.13.14 运行时(已裁剪, 免安装)
  app\xyfz_auto\      程序本体
    ├ tools\adb\      ★ 自带 adb.exe(含 AdbWinApi/AdbWinUsbApi.dll)
    ├ config.yaml     全局配置(adb 路径/端口/阈值)
    ├ accounts.json   多开账号配置(GUI 里维护)
    ├ gui_timer.json  定时任务列表(GUI 里维护, 首次运行自动生成)
    ├ engine\         步骤引擎(loader/model/runner/ui_registry)
    ├ device\         adb_client / win_input
    ├ recognition\    模板匹配(template) + OCR(ocr)
    ├ gui\            PySide6 界面
    ├ assets\templates\   模板图库(采集新模板就加在这)
    └ assets\tasks\       任务脚本(YAML, 可自行编辑)
        ├ daily_all.yaml  日常全家桶入口(include parts\ 下的子任务)
        ├ parts\          子任务脚本
        └ tests\          调试/测试脚本

【验证这个包有没有被人改过】
包是别人转发/网上下载的，用之前建议先验一下：
  1) 解压后双击「验证完整性.bat」，它会自动算出包的 MD5 和 SHA256，
     再跟发布方的 .md5.txt 比对：
        [通过] = 与发布时一模一样，可以用
        [警告] = 被改过或下载不完整，重新下载
     没有 .md5.txt 时它也会把算出的两个值显示出来，自己跟发布页对。
     也可以把 zip 直接拖到这个 bat 上。
  2) 不想解压的话，PowerShell 里执行：
       (Get-FileHash "鸡驴助手_vX.Y.Z.zip" -Algorithm MD5).Hash
     跟发布方给的 MD5 对比即可（不区分大小写）。

小提醒：MD5 能发现"包被换过"或"下载坏了"，但它只是指纹、不是防伪证书 ——
  想更保险，就让发布方把 MD5 单独发一次（比如包放网盘、MD5 发消息），
  这样连"包和校验文件被一起换掉"也能防住。

【快速开始】
1. 本机需已安装 MuMu 模拟器并开启 ADB 调试(设置→其他→ADB调试)。
2. 双击「启动助手.bat」。
3. 左侧控制面板:选任务脚本 → 连接设备 → 开始任务。
4. 换电脑/换端口:只需改 app\xyfz_auto\config.yaml 里的 device.port，
   adb 路径无需再配置(见下节)。

【adb 说明 —— 换电脑连不上时先看这里】
本包已内置 adb.exe（约 6.6MB），程序会按以下顺序自动查找并选用
第一个真实存在的，任何一级命中即可用：
  1) config.yaml 里 device.adb_path 指定的路径（若填写且文件真实存在）
  2) 本包自带 app\xyfz_auto\tools\adb\adb.exe   ← 默认走这个
  3) 系统 PATH 环境变量里的 adb
  4) MuMu 模拟器常见安装位置（自动扫描 C/D/E 等各盘符）

因此：
· 全新机器解压即用，不需要单独安装 adb，也不需要改配置。
· MuMu 装在 C 盘、D 盘或自定义目录都无所谓。
· 连接成功后，界面状态栏会显示 adb 来源
  （如"adb: 包内自带"），换机排查时一眼能看出用的是哪份。

如果确实要用 MuMu 自带的那份 adb：
  打开 config.yaml，把 device.adb_path 写成真实全路径，例如
      adb_path: "D:/MuMu/nx_main/adb.exe"
  注意盘符别写错——写了不存在的路径会被自动跳过，回退到包内自带。

【多开(最多5账号)】
- MuMu 多开器开多个实例, 每实例 ADB 端口不同
  (默认 16384 起每实例 +32: 16384/16416/16448/16480/16512,
   以 MuMu 多开器显示的实际端口为准)。
- 每个实例里先把对应游戏账号手动登录好(记住密码)。
- GUI「多开管理」页: 填端口 → 选脚本 → 设错峰延迟(分钟) → 保存 → 启动全部。
- 各账号日志: app\xyfz_auto\logs\run_<端口>.log

★ 多开时怎么分别看每个账号 (v1.2.1 新增)
  各账号跑在独立子进程里, 运行时会把画面/步骤/日志实时回传主界面:
  · 「实时画面」页顶部下拉选账号; 下方一排缩略图是所有账号的当前画面,
    点一下即可切成大图。点大画面依然可以拾取坐标(多开时也能取模板)。
  · 「实时步骤」页顶部下拉可只看某个账号(默认"全部账号");
    多账号并行时每行前面带 [账号名] 前缀, 并按账号分段显示。
  · 左侧「多开管理」选中某行 → 点「📺 看选中账号画面」可直接跳过去。
  · 回传数据写在 logs\live\port_<端口>\ ; 任务结束后仍可回看最后的画面与步骤。
  · 若某账号显示"子进程已退出(未见结束事件)", 说明那个号被强杀或崩了,
    去 logs\run_<端口>.log 末尾看原因。

【定时任务】
GUI 左侧定时列表: 添加时间+脚本(+账号), 到点自动执行;
勾选多个账号可实现全家桶多号错峰执行。
注意: 同一模拟器端口同一时刻只允许一个任务，程序用跨进程锁保护，
      重复启动会被拒绝而不是把界面点乱。

【退出与残留进程】★ 删不掉文件夹时看这里
- 点窗口右上角 X【不等于退出】: 程序会最小化到右下角托盘, 进程仍在后台跑。
  要彻底退出: 右键托盘图标 → 退出。
- 有任务在运行时点"退出"会先弹确认框, 避免误杀正在跑的任务。
- 退出时程序会自动收尾: 停任务 → 回收多开子进程 → 收回自带 adb server →
  释放日志文件与设备锁。正常情况下关掉就能直接删文件夹。
- 仍然删不掉(提示"文件正在被另一个程序使用")时, 双击:
      清理残留进程.bat
  它会结束所有【从本包目录启动的】python/pythonw/adb 进程, 不会动系统 Python
  和 MuMu 自己的 adb。之后即可删除整个文件夹。
- 若提示需要管理员权限: 右键「清理残留进程.bat」→ 以管理员身份运行。
- 重复双击启动不会再开出第二个窗口: 程序已在运行时会把已有窗口切到前台
  (可在 config.yaml 的 app.single_instance 关闭该行为)。

【常见问题】
- 提示"未找到 adb.exe": 确认 app\xyfz_auto\tools\adb\adb.exe 存在；
  若被杀毒软件删了，从压缩包重新解压该目录即可。
- 提示"连接失败": 依次检查
    ① 模拟器是否已开机；② ADB 调试是否已开；
    ③ config.yaml 的 device.port 是否与该实例实际端口一致。
- 双击启动无反应: 用「启动助手(调试).bat」看报错。
- 迁移配置: 拷贝 accounts.json / gui_timer.json / config.yaml 即可。
- 界面文字显示为方块: 缺少中文字体, 安装任意中文字体即可。

v5.6.0 (2026-10-19)
- 运行历史落盘 + GUI「运行历史」页签。这一版给"每次任务到底跑成什么样"一个可回看
  的记录，不用再靠当时盯着屏幕或翻日志。
  · 每次任务跑完（无论成功/失败/手动停止），子进程都会把这一轮的结果写进

  · 记录内容：结束时间、端口/账号、任务名、最终结论（完成/失败/已停止）、
    失败步骤清单、条件未命中清单（不计入真失败，单列一行"属正常"）、
    以及这一轮的性能数据（截图多少次、OCR 多少次、复用/热点省掉多少次、占多少时间）。
  · GUI 右侧新增「运行历史」页签：左边一张表列所有记录（按结束时间倒序，最近在上），
    点任意一行右边展开这一轮的详细汇总。结论用颜色标（完成绿/失败红/停止橙）。
    切到这个页签会自动从磁盘重新读，所以刚跑完的记录立刻就能看到。
  · 顺带修了两类会让一轮空转或误报的 bug：
    - 【主界面误判】以前在背包/角色/坐骑等子面板里也会被判成"主界面"，
      于是子页面起跑整轮在循环里空转还不报错。现在"主界面"明确排除这五个子面板。
    - 【每日必领重复跑必报失败】礼包/扫荡/捐献类步骤，第一次领完、第二次再跑没得领时
      会报真实失败。给这 9 个步骤标了"条件探测"标记（领完/没得领属正常，不计真失败），
      重复跑不再误报。

v5.5.0 (2026-10-19)
- 这一版不动玩法逻辑，只把"看"和"等"的成本压下去。上一轮完整日常实测 27.8 分钟
  里，真正的点击滑动只有 6 分钟，其余都花在重复截屏、重复识别和写死的等待上。
- 快在哪儿：
  · 每次操作前都会自动检查一次"设备还在不在"，这一步单次要 0.13 秒，一轮要跑七百
    多次。改成只在真的失败时才重连重试 —— 既省掉常态开销，掉线时也不会更差。
  · 点击后的固定小停顿从 0.3 秒收到 0.12 秒（实测点一下本身只要 0.135 秒）。
  · 截屏换成不带压缩的原始像素（684 毫秒 → 393 毫秒）。慢的本来是模拟器那边的
    PNG 压缩，不是传输；一轮日常要截几百次，这一项省得最多。若某台机器的格式
    认不出来，会自动退回原来的方式，不会出错。
  · 同一个画面不再反复截、反复认：2 秒内复用上一张；一旦点了/滑了，立刻作废。
  · 画面**没变**时连识别都省掉（比如等着某个界面刷出来，画面静止会被反复认 1.5 秒）。
    判定用缩略图逐格比对，一个数字变了就认得出；为了保险，最多连省 2 次就必须真识别一次，
    而「看面板是否已完成」这类验收判定**永远看新画面**，不走这条捷径。
  · 识别可以只看屏幕的一条横带，或只看"上次这个词出现的位置"（省掉约 2/3 时间）；
    没找到就照常整屏识别，所以不会漏判。
  · 等待的轮询间隔从 1 秒收到 0.3 秒 —— 一次轮询本身就要 2.8 秒，再睡满 1 秒是纯空转。
- 每轮结束会多打一行"性能统计"：截图多少次、OCR 多少次、有多少被复用/热点省掉、
  共占本轮多少时间。以后哪一版变慢了，看这一行就能定位。
- 顺带查明两件事：把截图缩小再识别**没有用**（0.75/0.6/0.5 倍实测反而更慢）；
  按矩形裁区域会把长标签截成半截（"今日多倍次数：10/10"→"倍次数：10/10"），
  所以区域裁剪只按纵向裁带、横向保持整行。

v5.2.0 (2026-10-19)
- 修「脚本运行中弹出黑色命令行窗口」：实测不是脚本本身——所有 adb 调用都做了隐藏处理，
  对照实验（同一台机器，6 次 adb connect）不带隐藏参数会弹 6 个窗口，带了就 0 个。

  现在：等主界面要同时确认"画面里没有回合/自动中/逃跑"，稳检从 3 秒提到 8 秒；
  复核给足 15 秒并先用模板快判；两个环各加"最多转 6 次"的守卫，超了就直接收尾，
  不会再无限转下去。
- 顺带修：点「前往」没生效时，原来只认"还停在介绍页"，实际表现是**退回玩法面板**，
  于是漏判后继续往下走、白等很久。现在两种都认，并回到批次循环重试。
- ★ 崩溃能查了：以前闪退只留一行"access violation / 没有 Python 栈"，什么都不知道。
  现在会记下三样东西——崩溃前正在做什么（截图/识别/点击哪一步）、每 30 秒一份
  全线程快照、以及崩溃地址落在哪个 DLL（形如 xxx.dll +0x偏移）。后一项不需要
  管理员权限，崩溃日志里直接就能看到。

v3.0.4 (2026-10-16)
- ★ 加 goto 死循环保护(引擎级, 不改界面)
  · 背景: v3 跑域外日常时 GUI 整个消失、run.log 卡在步骤 875↔878 反复打转,
    进程被强杀才停。根因 = 引擎 run_task 里 goto 只做 `idx = target; continue`,
    没有任何访问计数 —— 当 on_fail:{goto: X} 回跳的目标依赖的条件始终不成立时,
    形成无限循环(实录 875「等打完回主界面」↔ 878「复核仍主界面」),

  · 修复: 给每个 goto 目标记"被跳转次数", 超过 engine.goto_loop_limit(默认 30)
    即判定疑似死循环, 任务终止并打出清晰告警(指出是哪个步骤、被跳了多少次、
    疑似原因), 而不是永远空转。
  · 可调: config.yaml → engine.goto_loop_limit(默认 30)。若 legit 脚本需要更长
    等待(但正常等待请用 wait 超时, 别用 goto 空转), 调大即可。
  · 另加全局步骤执行上限(= max(步数×20, 3000))作兜底, 防任何形式的不收敛循环。
  · 验证: 构造 on_fail:{goto:自身} 的脚本, run_task 在第 31 次跳转时自动终止,
    返回 False 并打印死循环告警(见 wb_goto_loop_test.py)。

v3.0.2 (2026-10-16)
- ★★ 修「托盘右键退出也退不掉」—— 这是真 bug, 不是操作问题
  · 现象: 走的是正确路径(右下角托盘图标右键 → 退出), 程序却没退,
    v2 的进程从上午挂到下午才被发现。
  · 根因(已写最小程序复现对照验证):
      Qt 只在"最后一个**可见**的窗口被关闭"时才结束事件循环。
      窗口早就 hide() 到托盘了, 此时再 close() 不产生可见性变化,
      Qt 就不认为"最后一个窗口关了" → app.exec() 永不返回 → 进程一直活着。
      对照: 窗口可见时直接退出 → 正常; 先隐藏再退出 → 卡住。
  · 修法: 真退出分支末尾显式调用 QApplication.quit(), 不再依赖 Qt 的隐式判定。
  · 附带修: 有任务在跑时的"确认退出"对话框, 在窗口已隐藏的情况下会不可见
    (用户看不见框, 程序就卡在模态里叫不应)。现在会先把窗口拉回来再问,
    点"否"则恢复成隐藏状态。

v1.6.3 (2026-09-29)
- ★ 修复"启动多开账号时弹出一个黑色命令行窗口"(通常是账号2~5)。
  · 根因: 绿色版 GUI 由 pythonw.exe 启动(本身没有控制台), 多开账号要拉
    run_one.py 子进程。子进程用的是控制台程序 python.exe, 而作业对象
    (Job Object)那条启动路径漏了 CREATE_NO_WINDOW 标志, Windows 便给
    子进程新分配了一个控制台窗口 —— 就是你看到的黑窗。
    账号1 端口与本机相同、走的是 GUI 进程内线程, 所以最早在多开账号上暴露。
  · 修复: 该路径同样带上 CREATE_NO_WINDOW; 黑窗不再出现(已真机复现+回归)。
  · 行为不变: 子进程仍绑作业对象, 日志照旧写 logs\run_<端口>.log。

v1.6.2 (2026-09-28)
- ★ 修复"关闭程序后仍有残留进程, 必须先结束进程才能删除文件夹"。
  · 根因一: 点 X 只是最小化到托盘, 进程仍在后台运行(旧版提示不够醒目)。
    现在最小化提示会明确写出"进程仍在后台"+ 怎么彻底退出; 真正退出前若
    有任务在跑会二次确认。
  · 根因二: 多开子进程(run_one.py)在主窗口关闭后可能变成孤儿进程继续跑。
    现在子进程统一绑到 Windows 作业对象(Job Object)上并开启 KILL_ON_JOB_CLOSE
    —— 主进程一退出(含崩溃/被强杀), 系统会自动回收全部子进程。
  · 根因三: 自带 adb server 占着 tools\adb\adb.exe; 日志文件句柄占着 logs\run.log。
    现在退出时自动: 收回【本包】adb server(不碰 MuMu 自己的 adb)、关闭日志句柄、
    释放设备互斥锁。
  · 新增 清理残留进程.bat: 万一还有残留, 双击一次即可清干净(也可 --list 只查看)。
  · 新增单实例保护: 重复双击启动不再开第二个窗口, 而是把已有窗口切到前台。
  · 加固: logs\run.log 被占用时自动改用 run_<PID>.log, 不再因此启动失败。
