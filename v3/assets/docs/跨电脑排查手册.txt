  鸡驴助手 —— 跨电脑排查手册 (v1.6.9)
════════════════════════════════════════════════════════════
  本手册提炼自开发机多轮事故排查经验，供另一台电脑
  独立排查问题使用。排查完把"回传清单"里的文件发回
  开发机，即可继续深入分析。

────────────────────────────────────────────
一、新电脑首次部署（必做）
────────────────────────────────────────────
1. 解压 zip 到任意目录（路径不要含特殊字符），双击「启动助手.bat」。
   ★ 包是别人给的/网上下载的，建议先验证一下再装：
     解压后双击「验证完整性.bat」，显示 [通过] 说明和发布时一模一样；
     显示 [警告] 就是被改过或下载坏了，重新下载，别将就着用。
     不用解压也行：PowerShell 里执行
       (Get-FileHash "鸡驴助手_vX.Y.Z.zip" -Algorithm MD5).Hash
     跟发布方给的 MD5 对一下。
2. 迁移配置：从旧电脑拷 accounts.json / gui_timer.json / config.yaml
   （GUI 数据目录，见下方"文件位置"）。
3. ★ 必做：重新校准 win 鼠标通道
   - 原因：win 通道的坐标换算参数 (scale_y / y_offset) 是每台
     电脑按自己的 MuMu 窗口尺寸校准的，直接拷 config.yaml 会点偏。
   - 方法：命令行进入 app\xyfz_auto\，运行
       runtime\python.exe scripts\calib_win.py
     把输出的 scale/y_offset 填进 config.yaml 的 win_input 段。
   - 校验：GUI 左侧「窗口诊断 (win 通道)」按钮，确认找到的
     窗口数量与目标实例正确。
4. 端口确认：MuMu 多开实例的 adb 端口要与 accounts.json 一致
   （默认序列 16384, 16416, 16448 …）。

────────────────────────────────────────────
二、文件位置速查
────────────────────────────────────────────
  运行日志        logs\run.log          （主日志，全部步骤带时间戳）
  多开账号日志    logs\run_<端口>.log   （每个多开子进程一份）
  失败现场截图    logs\debug\step<N>_<步骤名>_<时间戳>.png
                  ★ 每次步骤失败自动截图，排查第一现场
  GUI/账号数据    与程序同目录或 %APPDATA%（accounts.json 等）
  config.yaml     app\xyfz_auto\config.yaml

────────────────────────────────────────────
三、常见问题速查表
────────────────────────────────────────────
【症状】启动多开账号弹黑色命令行窗口
  → 版本低于 v1.6.3 的已知 bug。换 v1.6.3+ 即可，脚本不受影响。

【症状】师门/五环"点前往/点师傅"后介绍页关不掉，任务显示未完成
  → ① 看日志是否出现 [win通道]：win 通道只说明"点了"，
    不代表点对了位置。窗口尺寸与本机不同会点偏 → 重跑 calib_win.py。
  → ② 该账号若是固定队【队员】：点前往被游戏静默拒绝是设计行为
    （队员被禁），脚本会 12 秒内识别并快速收尾，属正常。
    判别法：手动在介绍页真点一下"前往"——页面关=能做，没反应=被禁。
  → v1.6.4 起师门首选 adb 点击（与五环一致），win 只作兜底，
    本症状在 v1.6.4 上应大幅减少。

【症状】域外"卡在玩法面板"不动
  → 多数情况不是卡死：每批打完必须重开面板查进度（面板卡片上的
    次数是打开那一刻的快照、不实时；真实进度看介绍页），且队员号
    点完前往后"等战斗出现"最长空等 6 分钟。
    看日志：只要"查额外次数"的数字在涨（如 2/50 → 24/50）就是
    正常推进，等它到 50/50 或出"已完成"徽标即收尾。

【症状】点"停止"后要等很久才停
  → v1.6.2 起所有等待已改为 0.1 秒切片可中断，正常 <1 秒响应。
    若仍慢，回传 run.log 尾部（看是否卡在长 timeout 条件等待）。

【症状】弹"设备被其他任务占用"
  → 设备锁按端口互斥。确认没有两个 GUI 实例同时跑同一端口
    （任务管理器搜 pythonw.exe）。锁文件在 %TEMP%\xyfz_auto_locks\，
    确认无进程运行后可手动删。

【症状】步骤报"等待条件 超时"后任务直接终止
  → v1.6.2 起关键步骤都有恢复块，正常不应终止。回传 run.log
    尾部 + 对应 step<N>_*.png 截图。

────────────────────────────────────────────
四、排查现场回传清单（发回开发机用）
────────────────────────────────────────────
1. logs\run.log 的最后 200 行（或整个文件，几百 KB）
2. logs\debug\ 里最新的几张 step<N>_*.png（报错现场）
3. config.yaml（如涉及连接/点击问题）
4. GUI 标题栏或"关于"里的版本号
   ★ 排查"点了没反应"类问题时，顺带 grep 日志：
      findstr /c:"改用 adb 点击" logs\run.log
      findstr /c:"未找到 MuMu 窗口" logs\run.log
   出现任一条 = win 通道不可用已降级 adb，而 adb 会被游戏
   反注入吞点击 —— 表现就是"点了没反应"，需重新校准窗口。

────────────────────────────────────────────
五、包完整性与自检工具（app\xyfz_auto\_build_scripts\ 外发时含于开发机）
────────────────────────────────────────────
  解压后冒烟自检：verify_zip.py 的结论已在打包时验证过；
  日常怀疑包损坏时，重新解压对比即可。
  脚本改动排查：改 yaml 后必须重启 GUI 才生效（配置启动时加载）。

────────────────────────────────────────────
六、把整个项目搬到另一台电脑（开发/调试级）
────────────────────────────────────────────
绿色包只能"跑"；要在另一台电脑上改脚本、排查、重新打包，按下面做：

1. 拷贝源码目录（开发机上的 Claw\xyfz_auto 整个目录），
   可排除 logs\ shots\ __pycache__（运行数据，无必要）。
   _build_scripts\（打包/验收/回归脚本）务必一起带走。
2. 新电脑装 Python 3.13，然后建虚拟环境并装依赖：
       python -m venv venv
       venv\Scripts\pip install -r requirements.txt
   （含 opencv/numpy/pillow/pyyaml/rapidocr/PySide6/pywin32 等）
3. MuMu 12 模拟器 + 游戏装好；adb 路径保持 "auto"（包内自带优先，
   换机器无需改配置），config.yaml 的 device.port 改成该机实例端口。
4. ★ 重新校准 win 通道（calib_win.py，同第一节第 3 步）——
   两台电脑的窗口尺寸不同，校准值互不通用。
5. 验证：跑 GUI → 窗口诊断 → 手动执行一次小任务；
   回归脚本在 _build_scripts\ 下（test_*.py），用 venv python 跑。
6. 注意：开发机的会话记忆/工作日志不随项目走，本手册"铁律备忘"
   就是它们的精华版；排查中形成的新结论请直接批注在本手册上。

────────────────────────────────────────────
七、回传后的协作方式（推荐流程）
────────────────────────────────────────────
  另一台电脑：按第四节收集现场 → 发回
  开发机：    对照日志/截图定位 → 改代码 → 出新版 zip
            → 换包（替换 app 目录或整体解压覆盖，先停任务关 GUI）
  小版本迭代频繁时，认准 zip 文件名里的版本号，别用旧包覆盖。

────────────────────────────────────────────
八、改脚本时怎么加"界面可调选项"（v1.6.6 起）
────────────────────────────────────────────
  GUI 右侧「脚本选项」页: 左侧是脚本列表(运行(全局) + 当前任务里 include 的
  每个脚本, 有选项的标 ●), **选中哪个脚本, 右边只显示那个脚本自己的选项**。
  选项声明写在脚本自己的 yaml 里(options: 段), 界面自动扫描, 不用改程序。

  示例（写在 assets\tasks\parts\你的脚本.yaml 顶部）：
    options:
      script: parts/你的脚本.yaml   # 归属脚本(可省, 省=本文件)
      title: 我的玩法
      items:
        - key: my_mode          # config.yaml 里写的键
          section: my_task      # 写进哪个节
          label: 模式
          type: choice          # choice / bool / int
          default: "fast"
          choices:
            - {text: 快速, value: fast}
            - {text: 稳妥, value: safe}
          help: 说明文字
    steps:
      - name: 我的玩法-分支
        jump: "我的玩法-{{cfg:my_task.my_mode}}"

  · {{cfg:节.键}} 在加载脚本时替换（include/loop 展开后）；config.yaml 缺这个键时
    自动用脚本里声明的 default 兜底，所以不会因为没在界面动过就跑不起来。
  · 类型：choice 下拉 / bool 勾选（渲染成 true、false 字符串）/ int 数字（可写
    min,max,step,unit）。
  · 改完 options: 后在界面点「重新扫描脚本」；config.yaml 的值由 GUI 启动时读取，
    想立刻生效就重启 GUI。
  · 新脚本加选项后，若要在另一台电脑也看到，需要把脚本文件同步过去（或整体换包）。

────────────────────────────────────────────
九、针对单个子脚本改/调试（v1.8.0 起）
────────────────────────────────────────────
  右侧「脚本(YAML 可编辑)」和「脚本步骤」两页，顶部都有一个「脚本:」下拉框：
  · 选「整个任务」= 总脚本 / 全部步骤（和以前一样）
  · 选某个子脚本（parts\xxx.yaml）= 只看这一个玩法

  「脚本」页：选中子脚本后直接在编辑器里改它，Ctrl+S 保存写回**它自己**；
  点「开始任务」时，未保存的改动也只会写回编辑器正在开的那一份（不会把子脚本
  的内容误覆盖到总脚本上）。
  「脚本步骤」页：只列这个子脚本的步骤，方便定位；**列表里的序号始终是"整个
  任务里的第几步"**，所以「▶ 从选中步骤开始跑」依然从正确位置开始（补跑地煞/
  师门某一段特别省事）。

  以后新增玩法脚本：只要被总脚本 include 进来，这两个下拉框会自动多出一项，
  不用改程序。

────────────────────────────────────────────
十、在界面里新建脚本 + 用按钮库快速写（v1.9.0 起）
────────────────────────────────────────────
  · 左侧「＋ 新建脚本…」（或 Ctrl+N；「脚本」页右上角也有同款按钮）：
      1) 填脚本名（自动补 .yaml，重名会问要不要覆盖）
      2) 选存放位置：顶层任务(assets\tasks\) 或 子脚本(assets\tasks\parts\)
      3) 选起点模板：骨架模板（带注释、示例、兜底写法）/ 空白 / 复制当前编辑器里的脚本
      4) 右边就是脚本内容，可以直接改
      5) 勾"同时把 include 追加到当前任务" → 创建后总脚本末尾自动多一行 include，
         两页的「脚本」下拉里立刻就能看到它（**不勾的话，下拉里不会出现**，
         因为下拉列的是"被当前任务 include 进来的子脚本"）
    子脚本骨架已按项目约定开头「确认在主界面」、结尾「等回主界面」，直接接着写就行。

  · 左边「按钮库(双击 → 插到右边光标处)」/ 「脚本」页的「插入按钮/界面…」(Ctrl+B)：
    把 assets\ui_registry.yaml 的 18 个界面、121 个按钮摊成一棵树（可搜索），
    选中 → 选"插入形式" → 双击就生成能直接粘进 steps 的 YAML 片段：
      · 完整步骤（含 timeout/retry/on_fail 兜底，推荐）
      · 完整步骤 + 先等所在界面出现
      · 只动作 click: {button: X} → 接到某个已有步骤里（这种片段缩进是 4 空格，
        因为 YAML 里 `- name: X` 的键从第 5 列开始，缩进 2 会被当成另一个映射而报错）
      · 界面节点：wait: {ui: 界面} / goto: {ui: 界面}（会提示有没有 opens 导航路径）
    好处：不用再记按钮叫什么、坐标多少；写出来的脚本换分辨率/换机器也不会点偏。

【铁律备忘】(历史事故换来，勿删)
  · OCR 判定必须写在文字实际所在界面（50/50 只在介绍页，
    面板卡片上 OCR 认不出 —— 在错误界面判定会死循环）
  · 域外收尾条件 = 介绍页 50/50 或 面板「已完成」徽标，二选一命中即收
  · 战斗出现判定必须多信号：回合/自动中/逃跑（组队战斗无"回合"字样）
  · 固定队队员点前往被静默拒绝 = 设计行为，不是 bug
  · win_input 的 scale/y_offset 是本机校准值，换机器必须重新校准
