## 1. P0 — 正确性与合规（建议先做）

### P0-1 失败会被报成成功（用户清单 P0-①，仍未修）
- **证据**：`engine/runner.py:642-691`。`on_fail: continue` **183 处**、`on_fail:{goto}` **96 处**、`on_fail: stop` 10 处；`on_fail: continue` 仍 `return True`，失败只进 `failed_steps`，任务照样判成功。
- **更严重**：`required: true` 全项目**只在注释里出现过 1 次**（`assets/tasks/每日必领.yaml:506`），**实际零使用** → `has_required_failure()`（runner.py:745-747）从未生效，「关键步骤失败即整条失败」的保护是空转。
- **后果**：昨夜 157 步跳过，汇总只说 16 步未做成，无法区分「条件检查没命中（正常）」与「真失败了」。
- **方案**：
  1. 新增 `optional: true`（或 `on_fail: skip`）语义：命中=正常跳过，与真失败**分开计数**；
  2. 给导航类「理论上必然能做到」的步骤标 `required: true`（按 2026-10-16 约定，奖励类步骤别标）；
  3. Engine 返回**结构化** `(ok, failed_list)`，GUI 汇总分两行显示「失败 N / 条件未命中 M」。
- **工作量**：中（引擎 + 脚本标注 + GUI 汇总）。**需重打包**。

### P0-2 引擎异常捕获面太窄，一次意外整条报废
- **证据**：`runner.py:615` 只捕获 `(ValueError, KeyError, TypeError, NotImplementedError)`；`DeviceError / OSError / cv2.error / ImportError` 全部漏出，而 `run_task` 外层（750-837）只有 `except _Goto` + `finally` → adb 掉线、rapidocr 缺失、模板通道异常会**直接抛出**，没有失败汇总、没有现场截图。
- **方案**：补 `except Exception` 兜底 → 记账 + 落现场截图 + 汇总后再重抛；OCR `_ensure()` 的 ImportError 单独给「OCR 不可用」总告警（现在 185 处 `wait:{ocr:}` 会逐条 warning 刷屏）。
- **工作量**：小。**需重打包**。

### P0-3 便携版外发的合规与隐私
- **证据**：运行后便携版目录会生成 `app/xyfz_auto/gui_settings.json`（当前内容 `{"dont_show": true, "version": 3}`）＋ `accounts.json`（我的 5 个端口账号表）＋ `logs/`（含 134MB 游戏截图）。打包脚本已正确排除这些（`tools/build_portable.py:44-51`），但**运行一次就又长出来**，外发时等于把「我已同意声明」+我的账号+游戏截图一起送出去，而声明第 7 条明确要求「对外分发须完整保留本声明」。
- **方案**：打包脚本自检增加三项（禁 `gui_settings.json` / `accounts.json` / `logs/`）；另加一个 `外发前清理.bat`（清 logs、__pycache__、个人配置，保留 accounts 空表）。
- **工作量**：小。**需重打包**。

### P0-4 版本号四处同步无自动校验
- **证据**：仍靠人肉同步 `common.py` / `__init__.py` / `使用说明.txt` / `README.md`。打包自检（`build_portable.py:99-142`）只查关键件/硬编码路径/缓存残留，**不查版本一致性**。
- **方案**：自检里加一条——从 `common.py` 读 `APP_VERSION`，校验另三处都匹配，不匹配即报错中止。
- **工作量**：极小。**需重打包**。

## 2. P1 — 稳定性与运行体验

### P1-1 GUI 主线程仍有阻塞点（卡顿未根治干净）
| 位置 | 行为 | 影响 |
|---|---|---|
| `main_window.py:1529` | 「截图」按钮在主线程跑 `screencap`+`_ensure_connected` | 在线 ~0.6s，**端口没开时 4.6s**，最坏 20s+ 冻结 |
| `main_window.py:1405` / `registry_panel.py:310` | 采集模板内部同步调截图 | 同上 |
| `main_window.py:1394` / `registry_panel.py:296` | 主线程 `matcher.reload()` 重读全部模板 | 数十~数百 ms |
| `main_window.py:2032` | `_poll_live` 每 600ms 主线程逐端口 `imdecode` | 5 端口叠加 30-75ms/周期 |

- **方案**：截图/采集全部走后台线程（复用已有的「线程 + 结果队列」模式）；模板改为增量加载单张；`_poll_live` 提到 800-1000ms、缩略图用 `FastTransformation`。
- **工作量**：中。**需重打包**。

### P1-2 跨线程共享可变状态（潜在随机崩溃）
- **证据**：`main_window.py:1809-1813` 的 worker 信号全用 `connect(lambda...)`，未指定 `Qt.QueuedConnection`；`worker.py:49` 的 `reload()` 会 `templates.clear()` 重填，而主线程可能同时 `names()`/再次 `reload()` → 可能 `RuntimeError: dictionary changed size during iteration`；`ui_registry` 被 worker 读的同时面板可写盘。
- **方案**：信号显式 `Qt.QueuedConnection`；matcher 用「生成新 dict 后整体赋值」的快照切换；任务运行期间注册表只读。

### P1-3 worker 线程生命周期 / 退出硬崩风险
- **证据**：`main_window.py:379-384` `worker.wait(5000)` **超时后照样继续并最终 `app.quit()`**；旧 `TaskWorker` 从不 `disconnect/deleteLater`。典型症状 `QThread: Destroyed while thread is still running` 硬崩。
- **方案**：接 `finished` 做 `deleteLater()`；超时后 `terminate()`+`wait()`，并把情况写进 `crash.log`。

### P1-4 句柄泄漏（"文件夹删不掉"的根源之一）
- **证据**：`main_window.py:2009-2034` 的 `_readers` **只增不减，全项目无一处 `rd.close()`**（已 grep 确认，退出收尾也没关）；`multi_panel.py:253` 日志文件句柄 `open(..., "a")` 从不 close；`crash_guard.py:59` 的 faulthandler 句柄常驻。
- **方案**：端口消失/超时后 close；`_full_shutdown` 遍历关闭；crash 句柄纳入退出收尾。

### P1-5 debug 截图无保留策略
- **证据**：一晚 157 张 / 134 MB（`logs/debug/`），全部常驻。
- **方案**：按「保留最近 N 张（如 200）或 7 天」滚动清理，或默认只在失败步骤落图（现在已经是失败才落，但失败太多时仍爆）。

### P1-6 引擎语义坑（与昨夜跑 4 小时直接相关）
| 位置 | 问题 |
|---|---|
| `loader.py:282-289` | `goto` **两种语义**：顶层=界面导航，`on_fail:{goto}`=跳步骤名。极易写反 |
| `runner.py:580` | `tries = retry+1` 且**每次重试都重跑完整 timeout**：`daily_yuwai.yaml` 有 `timeout: 5400` + `retry: 1` → **单步最坏 3 小时** |
| `runner.py:331-342` | `settle>0` 时外层 `while True` **没有总 deadline**，`step.timeout` 失去约束 |
| `runner.py:795-816` | goto 计数把**成功路径的 `on_success.goto` 和 jump 回边**也算进去（如 `daily_claim.yaml:95` 15 次宝箱循环是合法回边）→ 长循环可能被误判死循环 |
| `ocr.py:28-36` | OCR 无超时/无异常包裹（单帧 ~2.4s）；关键词是朴素 `in` 匹配，无全半角/空格归一化（"师 门" 永久漏检） |
| `template.py:78-101` | 阈值写死 0.80，**yaml 里逐条调不了**；无多尺度，「模板比屏幕大」直接判未命中且无声 |

- **方案**（按收益排序）：① 给重试+settle 加**统一 deadline**（一眼解决"跑 4 小时"）；② goto 计数只统计 `on_fail` 引发的回跳；③ `goto` 步骤跳转统一改名 `jump`，loader 校验；④ OCR 加超时与归一化。
- **工作量**：中-大（① ② 小，③④ 中）。
