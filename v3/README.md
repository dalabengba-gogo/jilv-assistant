> **当前版本：v4.2.0**（2026-10-18）
> 改版本号时同步**四处**：`app/xyfz_auto/common.py` 的 `APP_VERSION` /
> `app/xyfz_auto/__init__.py` 的 `__version__` / `assets/docs/使用说明.txt` 版本历史 /

## v3 和 v2 是什么关系

| | 目录 | 版本 | 状态 |
|---|---|---|---|
| v2（旧，稳定在用） | `D:\鸡驴助手_dev\app\xyfz_auto` | v2.1.0 | **保持不动**，随时可回退 |
| **v3（新）** | `D:\鸡驴助手_dev\v3\app\xyfz_auto` | **v4.1.0** | 本次新建，源头改进版 |

两边是**各自独立的工程**，不是就地升级：

- v2 一行代码都没改，如果 v3 出问题，直接回去用 v2 即可。
- v3 的 YAML 任务脚本、模板库、按钮注册表是**从 v2 复制过来的副本**，
  之后在 v3 里改脚本不会影响 v2（反之亦然）。
- `vendor/` 是**目录联接**（junction），指向 `D:\鸡驴助手_dev\vendor`，
  共用同一份 337 MB 运行时，没有复制第二份。

## 怎么跑

- **从源码开发运行**：双击 `运行开发版.bat`
- **打包绿色版**：双击 `build.bat`（产物在 `dist\鸡驴助手_vX.Y.Z\`）
- **彻底退出程序**：菜单「文件 → 退出」或 `Ctrl+Q`（点窗口 ✕ 只是最小化到托盘，
  进程继续在后台跑——定时任务需要）。

### 打包约定（2026-10-18 起）

**每次改完版本，打包后必须产出一份同名 zip，方便拷去别的电脑测试。**
压缩是打包脚本的**默认行为**（`--no-zip` 才是跳过），不用记参数：

```
python tools/build_portable.py            # 打包 + 自动出 zip
python tools/build_portable.py --clean    # 打包前先把同名旧产物移走
```

- 用 **zip 不用 7z**：解压端零依赖，Windows 资源管理器原生支持，
  拷到没装压缩软件的电脑上双击就能解压运行。实测 332MB → **129.5MB（省 61%，约 40 秒）**。
- 同时生成 `鸡驴助手_vX.Y.Z.md5.txt`（官方 MD5 + SHA256）。
  绿色版内自带 **「验证完整性.bat」**，别人拿到包解压后双击它，就能验证包有没有
  被改过 / 下载坏了（与官方记录一致则显示 `[通过]`，不一致显示 `[警告]`）。
  注意：校验值**不能塞进压缩包内部**（那等于让篡改者自己改分数），必须是独立的一份。
  更保险的做法是包放网盘、MD5 另外单独发一次。
- 打包前会先做**产物卫生**，把就地运行长出来的个人文件移出包外：
  `logs`（运行日志+游戏截图，实测能到 235MB）、`shots`、`_collect`、
  `gui_settings.json`、`gui_timer.json`。
- ⚠ 卫生清理是**移走（rename 到 `dist/_trash_*`）而不是删除**：
  一是不需要删除权限（受限环境里批量删除会被拦，实测一次 4212 个文件就让打包胎死腹中）；
  二是万一里面还有没导出的排障截图还能捞回来。确认新包无误后，
  把 `dist/_old_*` 和 `dist/_trash_*` 整个删掉即可回收空间。
- 打包时固定排除 `gui_settings.json` / `gui_timer.json`（本机个人设置，不该跟着分发）。
  `accounts.json`（账号表）**会带上**，拷到自己别的电脑时账号能直接用；
  要外发给别人就手动删掉它，首次运行会自动重建空表。
- 打包完自检：关键件齐全 / 模板数 ≥50 / bat 无硬编码盘符 / 无 `__pycache__` 残留 /
  bat 必须 CRLF+GBK 且不含 chcp / 版本号几处同步 —— 任一条不过就打包失败。

## v3.0.0 相对 v2.1.0 改了什么

### 0. ★★ 程序根本退不出去（v3.0.2，真 bug）

**现象**：走的是正确路径（右下角托盘图标右键 → 退出），程序也没退——
实测 v2 从上午 10:13 挂到下午 13:17 才被发现（PID 35604），占着文件夹和 adb server。

**根因**（写了最小程序做对照实验验证）：

Qt 只在「最后一个**可见**的窗口被关闭」时才结束事件循环。窗口早就 `hide()` 到托盘了，
此时再 `close()` 不产生可见性变化 → Qt 不认为"最后一个窗口关了" → `app.exec()` 永不返回。

| 场景 | 结果 |
|---|---|
| 窗口可见时直接退出 | `app.exec()` 立刻返回，正常 |
| 先隐藏到托盘，再退出 | 事件循环 3 秒后仍在跑，**进程退不出去** |

而用户的正常操作顺序恰恰是后者。

**修法**：真退出分支末尾显式 `QApplication.quit()`，不再依赖 Qt 的隐式判定。
附带修：有任务在跑时的"确认退出"框在窗口隐藏时不可见（用户看不见框，程序卡在模态里叫不应），
现在会先把窗口拉回来再问，点"否"恢复隐藏。

### 0.1 关窗 ≠ 退出：得有个出口（v3.0.1）

**现象**：点窗口右上角 ✕ 关掉助手，以为退出了；实际进程一直在后台跑。

**原因**：✕ 只是"最小化到托盘"（定时任务要在后台跑，这是刻意的），
而唯一能真正退出的入口在**托盘右键菜单**里；托盘图标常被 Windows 折叠进隐藏区，
用户找不到图标就等于没有出口。原来那个"进程仍在后台"的气泡还只弹一次，没看见就再也不提。

**现在**：主界面加菜单栏「文件」（最小化到托盘 / 退出 `Ctrl+Q`），不依赖托盘是否可见；
每次隐藏都明确提示"程序没有退出"并给出两条退出路径。

### 1. ★ 失败不再被报成成功（最重要）

**问题**：脚本里 `on_fail: continue` 有 185 处，而 `continue` 在原实现里返回 `True`，
于是 `run_task` 判定整条任务成功 → 界面打 ✅、退出码 0。
实录：帮派捐献没做成却报"成功"（2026-10-11），完全无从察觉。

**现在**：每步失败都记账（`Engine.failed_steps` / `Engine.failure_summary()`）

| 情况 | 界面显示 |
|---|---|
| 全部做成 | `完成 ✔` |
| 有步骤没做成 | `⚠ 完成(N步未做成)` + 系统日志逐条列出第几步、叫什么、为什么 |
| 关键步骤失败（脚本里写了 `required: true`） | `失败` |

**为什么默认不把所有步骤都设成 required**：很多步骤"没做成"是正常的
（今天已领过 / 材料不够），一刀切会天天误报。所以默认只提示、不判失败；
需要严格盯的步骤自己在 YAML 里加 `required: true`：

```yaml
- name: 每日必领-⑥点材料捐献
  click: {button: 帮派材料捐献, mode: locate}
  retry: 0
  required: true          # ← 加了这行, 这步失败就整条任务判失败
  on_fail: {goto: 每日必领-⑥收尾}
```

### 2. ★ 图片读写不再"静默失败"

`cv2.imwrite` 写中文路径**返回 False 却不报错**；`cv2.imread` 读中文路径
**返回 None**。本项目装在含中文的目录下（如 `D:\鸡驴助手_dev`），两个坑都踩过：

- 点「从点击点采集模板」→ 提示"已保存"，文件其实没生成
- 模板库整个读不进来 → 表现出来却是每个步骤"等待超时"

现在统一走 `common.imwrite_unicode()` / `common.imread_unicode()`
（numpy 字节中转），并检查返回值。**项目里不要再写裸的 `cv2.imwrite`/`cv2.imread`。**

### 3. 清理了一批累赘

- 孤儿模板 2 个：`main_btn_wanfa`、`tuoguan_end_btn`（65/67 个模板在用，这两个没人引用）
- 零引用脚本 5 个：`win_click.py`、`make_shortcut.py`、`scan_waits.py`、`test_ocr.py`、`multirun.py`
- 死代码 5 处：`common._same_file`、`AdbDevice.wake_and_unlock`、
  `Engine.win_channel_status`、`MainWindow._show_screen`、`Ocr.find/find_all`
- 死配置项 4 个：`device.screen_size`、`device.density`、`engine.retry_times`、
  `app.log_dir`（代码零读取，留着误导人）
- 删掉了 `app/xyfz_auto/requirements.txt` —— 它和根目录那份**互相矛盾**
  （前者 PySide6/rapidocr 还注释着、版本宽松 `>=4.8`；后者精确锁定）。
  现在只有根目录一份精确的。

**没删的**：注册表里 100 个"任务中没出现"的按钮 —— 那是 UI 地图资产，
按钮库页和 `opens` 导航链依赖它。
